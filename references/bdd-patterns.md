# BDD 實踐參考

## 核心原則

BDD（Behaviour-Driven Development）的核心是用「可執行的規格」描述系統行為，讓開發、測試、業務三方對齊。

**好的 Scenario 具備：**
- 明確的角色（誰在做）
- 明確的前置狀態（系統現在的狀態）
- 單一的觸發動作
- 可觀察、可量測的結果

---

## Given / When / Then 使用規則

### Given（前置條件）

描述**系統狀態**，不包含動作。

```
✓ Given 使用者已擁有有效帳號且帳號未被停用
✓ Given 購物車中有 3 件商品，總金額 $1,200
✓ Given 今天是 2024-01-15，距離活動結束還有 3 天

✗ Given 使用者前往登入頁面並輸入帳號密碼  ← 含有動作
✗ Given 使用者登入                           ← 太模糊
```

**多個前置條件**可以用 And 連接：
```
Given 使用者已登入
And   使用者已有待付款訂單
```

### When（觸發動作）

描述**單一使用者動作**，是觸發行為改變的事件。

```
✓ When 使用者點擊「結帳」按鈕
✓ When 使用者輸入折扣碼「SAVE20」並點擊套用
✓ When 系統每天 00:00 執行排程任務

✗ When 使用者登入並前往購物車然後結帳  ← 多個動作
✗ When 使用者做了一些操作                ← 太模糊
```

### Then（預期結果）

描述**可觀察、可量測**的系統回應。

```
✓ Then 系統建立訂單，訂單狀態為「待付款」，並發送確認 Email 至使用者信箱
✓ Then 頁面顯示錯誤訊息「折扣碼已過期」，購物車金額不變
✓ Then POST /api/orders 回傳 201，回應 body 包含 orderId

✗ Then 顯示成功訊息     ← 不夠具體（什麼訊息？）
✗ Then 系統正常運作     ← 無法量測
✗ Then 流程完成         ← 沒有描述行為
```

## Story 粒度判斷

### 太大（需要拆分）

```
Story：使用者管理系統
```
→ 一個 Story 應該是一個使用者可以完成的具體功能，不是整個子系統

### 太小（可以合併）

```
Story：使用者輸入 Email
Story：使用者輸入密碼
Story：使用者點擊登入按鈕
```
→ 這三個是同一個功能（登入）的操作步驟，不是獨立的 Story

### 適當粒度

```
Story：使用者密碼登入
Story：使用者 Google OAuth 登入
Story：Admin 停用使用者帳號
```

## 常見反模式

### 1. 實作細節進 Scenario

```
✗ Given 資料庫 users 表中有一筆 email='test@example.com' 的記錄
✓ Given 使用者已成功完成 Email 驗證
```

Scenario 描述**行為**，不描述實作。測試工具（如 Cucumber）會把 Given 轉換為程式碼，但 Story 本身應該可以被業務人員閱讀。

### 2. 混合多個使用者動作

```
✗ When 使用者輸入帳號、密碼，勾選「記住我」，然後點擊登入
✓ When 使用者勾選「記住我」並點擊「登入」
  （帳號密碼的輸入可以放在 Given 裡）
```

### 3. Then 描述動作而非結果

```
✗ Then 系統傳送 Email 給使用者
✓ Then 使用者收到標題為「密碼重設通知」的 Email，Email 中包含有效期 1 小時的重設連結
```

### 4. 一個 Scenario 涵蓋過多 Then

```
✗ Then 系統建立訂單
  And 發送 Email
  And 扣除庫存
  And 更新使用者點數
  And 通知倉儲系統
  And 記錄 Log
```
→ Then 只列出使用者可觀察到的主要行為，系統內部的連鎖反應（Log、通知等）不需全部列出

## Scenario 命名慣例

**格式**：`[情況/角色] [動作/事件]`

```
✓ 正常登入成功
✓ 密碼錯誤累計達上限後鎖定
✓ 使用已過期的重設連結
✓ Admin 停用使用中的帳號

✗ Test 1          ← 沒有語意
✗ 登入功能測試    ← 太泛
```

## 邊界案例清單（通用）

針對任何功能，考慮以下邊界案例是否需要 Scenario：

**輸入相關**
- 空白/null 輸入
- 超過最大長度
- 特殊字元、Unicode
- 重複提交（double submit）

**狀態相關**
- 資源不存在
- 資源已被刪除/停用
- 資源已被他人鎖定
- 並發操作（兩人同時操作同一資源）

**權限相關**
- 未登入存取需登入的功能
- 已登入但無足夠權限
- 嘗試存取他人的資源

**時間相關**
- Token/連結已過期
- 優惠活動已結束
- 訂單超時未付款

**外部依賴**
- 第三方服務（Email、Payment）失敗
- 網路超時
